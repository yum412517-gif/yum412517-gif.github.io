### 2. 智谱发布 GLM-5.4 官方博文：首个 Loop Transformer，已向 Coding Plan 用户开放

[@ZixuanLi_](https://x.com/ZixuanLi_/status/2124719275864670681) 于 UTC **04:18:45 · 11-23**（约北京 **12:18**）发帖称，GLM-5.4 现已向全部 GLM Coding Plan 用户开放，并写 “New vision capabilities and stronger all-round coding performance”；对有周额度的用户，GLM-5.4 的额度较 GLM-5.3 高 **50%**。该账号简介自称 Lead，并标注 @Zai_org；[@Zai_org](https://x.com/Zai_org/status/2124719658074825004) 随即转发了这条帖。IT之家约 **12:49:30** 跟进时还写，V2、V3 及团队版用户使用 GLM-5.4 的额度已提升至 **1.5** 倍，将模型名设置为 glm-5.4 即可，并称在 Coding Plan 的模型列表中能看到「1M」和「视觉」字样。额度「**50%** / **1.5** 倍」只适用于宣布中提到的周额度，或 V2、V3 及团队版，不要写成所有套餐、所有调用方式都已经上调。

随后，官方博文 [GLM-5.4: Toward Generalized Coding with Our First Loop Transformer](https://z.ai/blog/glm-5.4) 已上线。今晚取出的页面仍未核到 `datePublished` 或 JSON-LD 时间戳，不以猜测补写发表时刻；[@Zai_org](https://x.com/Zai_org/status/2124805514722771349) 于 UTC **10:01:26**（约北京 **18:01**）发了介绍帖。博文写，标准 Transformer 每层在一次前向中只跑一遍，Loop Transformer 则让一组权值共享的层多次迭代、在上一轮隐状态上继续 refinement，从而在不增加参数量的前提下加深网络。文中称这一想法并不新，但从零预训练的循环模型在同等预训练算力下仍落后于非共享权值模型；他们采取的办法，是对已经预训练好的基座做持续训练，把它改造成 Loop Transformer。架构上，博文写 GLM-5.4 把 GLM-5 基座的 **28** 层循环跑两轮，并在 **750B** 量级上做了三项改动：Gated Progressive Updates、Hybrid KV Cache（文中称在 **1M** 上下文长度下，相对 GLM-5.3 的部署成本增加仍可控），以及 Sparse Attention Index Reuse。这里的 **750B** 是官方博文的「量级 / 基座」表述——今晚的原文是 “at the 750B scale”、“750B base models” 以及 “our 750B base”——不要自行改写成未经原文用词确认的「总参数 750B」。博文还自称，GLM-5.4 作为首个建立在 Loop Transformer 上的旗舰，其智力水平可与 **2T–3T** 参数量级的模型相比；这是官方自称，不是独立实测，也不能反过来把旗舰的总参数写成 2T 或 3T。文中同时写，它仍有局限，容易陷入过长的 “marathon thinking” 循环。

博文还写，他们在 **1B、4B、30B、750B** 基座上逐步验证了这一架构；在与 750B 基座同构的 **30B** 模型上做了等参数对照，称在参数量相同、总训练算力仅多约 **10%** 的情况下，循环版有明显收益，数学、科学推理和长上下文任务上的增益更大，且在 GPQA-Diamond、MMLU-Pro 等基准上平均输出长度下降 **10–14%**，主要来自更短的思维链。这些 **30B** 对照数字不能径直写成 GLM-5.4 旗舰本身的评测成绩。推理吞吐方面，博文自称 GLM-5.4 在低峰期可达每秒 **200** token，高峰期维持每秒 **70–80** token，并写这需要模型与推理基础设施的协同设计，不要当成独立实测。文中把 Generalized Coding 解释为在编码与视觉能力提升的推动下，把写代码的能力推广到生成和编辑视频、做完整游戏、以及 3D 建模与机械设计，并列了音乐视频、FreeCAD 六轴机械臂、完整游戏、以及用数学几何与自定义 GLSL 着色器做互动 3D 观鸟等演示方向。

官方博文给出的产品入口包括 [GLM Coding Plan](https://z.ai/subscribe)、[ZCode](https://zcode.z.ai/en)、[Z.ai Chat](https://chat.z.ai)，并写 API 为 Coming Soon，指向 https://z.ai/model-api；关于权重，博文写他们计划在完成必要的安全加固后，以负责任的方式开源。也就是说，现在不能写成全面 GA，不能写成权重已经开源，也不能写成 API 已经开放。博文末尾称 GLM-5.4 只是循环架构的第一步，他们并不在「加深」与「加大模型」之间二选一，并写下一个显著更大的模型会带走此处的经验，「It will be ready soon」。第一财经约 **17:57** 的快讯还转述，同步上线 ZCode、Trae、WorkBuddy、Qoder 等编码平台；其中 Trae、WorkBuddy、Qoder 不见于今晚取出的官方博文与 @Zai_org 介绍帖，须保留为第一财经报道口径。今晚没有核到旗舰基准分、API 价格或开源许可，也就不补写。

### 9. 补录 11-22：OpenAI 首席科学家谈困惑度与智力，数字来自内部持有集

官方博文 [Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence) 栏面日期为 **November 22, 2026**，作者是 OpenAI 首席科学家 Jakub Pachocki。文中建议把困惑度（文中等同于交叉熵损失，实际追踪的是对数困惑度）作为比较各家预训练进展、并据以讨论行业共同安全标准的指标，同时公布 OpenAI 内部持有集上的对数困惑度。作者写，自 GPT‑3.5 以来，他们主要在内部代码库来源的持有集上追踪这一指标（固定快照，文中所报数字即此）。文中给出的对数困惑度约为：GPT‑3.5 **~0.99**（流利对话，并构成最初 ChatGPT 的基础）、GPT‑4 **~0.91**（能有效使用思维链，并促使后来针对该能力做定向引出、形成现代推理模型）；当损失降到 **0.8 以下**，他们看到网络安全与数学等领域出现“变革性”能力；当模型达到约 **~0.76**，开始在他们用作评测的数学开放问题上产生“突破性”结果。作者强调，这些能力并不是事先就能断定会在这些精确阈值上出现。外推近期进展，文中写进入约 **~0.68–0.7** 的对数困惑度区间时，应预期还会出现更多变革性能力，但作者写自己并不知道那会是什么，今天也未必在测这些能力。**0.68–0.7** 是外推中尚未被文中称为已达到的窗口，不要写成已经跨过的成绩。

关于节奏，文中以数学开放题为类比，称一旦升级到约 **~0.76** 的模型，结果开始成批出现；并写深度学习研究里“最早在 **2027** 年，理论上也可能看到类似的预训练基础进展雪崩”（原文为 “as soon as 2027 we could conceivably see”）。**2027** 年是这一外推窗口，不是文中已经写明达到的时间表。作者建议前沿模型开发者共同建立评估规范，并在这类模型首次被使用前完成安全案例的红队测试；进一步提议基于困惑度及其他测量的共同限制，开发者承诺在理解与监控 AI 行为达到某一具体里程碑之前不越过该限制。这是一份呼吁建立行业标准的署文，不是已经生效的强制限额，也不是新模型发布。文中自己也列出将该指标用作共享尺度的困难：各实验室的评测集与训练数据混合不同，直接对比不易；困惑度并不对应某个人们直接关心的任务；预训练之外的进展——尤其是思维链推理——并不会降低模型达到的困惑度，却能大幅提升能力；以及不知道数据的固有熵，损失不可能到 0。这些内部数字不能写成可与他家模型直接对表的公开榜。

署文作者账号 [@merettm](https://x.com/merettm)（栏面显示名 Jakub Pachocki）于 UTC **17:03:00 · 11-22** 发了宣布帖；[@sama](https://x.com/sama/status/2124551594691932405) 于 UTC **17:12:27 · 11-22** 发帖称这是 OpenAI 一段时间以来发表的最重要内容之一，写他们正对预训练进展提供更多透明度，并希望行业能就共同限制达成一致。这是支持，不是新产品，也不代表 OpenAI 已代表全行业完成约定。微软 AI 负责人 Mustafa Suleyman（[@mustafasuleyman](https://x.com/mustafasuleyman/status/2124663594449318173)）于 UTC **00:37:29 · 11-23**（约北京 **08:37**）发长帖跟进，写他们完全支持这一透明度倡议；经 OpenAI 许可，在对方的评测集上公布 MAI-2 Base 的对数困惑度为 **0.819**，并称这与 GPT-5.6 Sol 基础模型处于同一量级（原文为 “same ballpark”）。作者写他们的模型与 OpenAI 使用同一分词器，因此这些数字可直接比较；但接着写，未来若要在各实验室之间比较，或许需要改报按字节计的比特数（BPB）而非困惑度，因为各家的分词器不同，也还需要不同的评测集——能使用 OpenAI 评测集是特例（原文为 “special case”）。该帖随后一条回复只链到 Microsoft AI 已于 **October 15, 2026** 发布的 *Frontier Pre-training at Microsoft AI*，用来指向 MAI Base 2 的既有技术说明，不是今天新的官方博，也不要把 Microsoft 的响应写成已经生效的行业共同限额。今晚约 **19:51**（北京时间）重新打开 [HN 50601525](https://news.ycombinator.com/item?id=50601525) 为 **602** 分。
