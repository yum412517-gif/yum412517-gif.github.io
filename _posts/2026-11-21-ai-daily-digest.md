## 工具与产品

### 1. 落到自己这边的几处入口：Gemini 在 Mac 上的 computer use，向 Plus 推开的 ChatGPT Space，以及 API 里按需加载的工具（头条）

这一组要分开看日期和资格，不要写成同一天、同一套许可证已经全开。

**Gemini 应用在 Mac 上的 computer use，以及 API 里的 Tool Retrieval（补录，官方日期 Nov 19, 2026）。** [blog.google 署文](https://blog.google/innovation-and-ai/products/gemini-app/computer-use-mac/)标题为 “Let Gemini tackle repetitive chores on your Mac”，作者为 Gemini App 集团产品经理 Michael Friedman，`pubDate` UTC **17:00:00 · 11-19** ≈ 北京 **01:00**。官方写从当天起，Gemini 应用在 Mac 上引入 computer use：你描述要做的工作，Gemini 会在隔离的后台窗口里点击、输入、打开菜单和填写表单，主屏幕和光标仍可继续使用，聊天里可以看到实时预览。你自行选择允许它访问哪些应用，并可随时暂停，在关键步骤先批准再执行。举例包括在设计软件里批量调色、从本地 PDF 提取信息去填运费报价、从多个仪表盘拉取指标做成幻灯片，以及根据本地照片做调研后上架二手平台。今晚打开的官方页写，该能力正在美国以英语滚动推出；脚注写明须为搭载 Apple Silicon、运行 macOS Sequoia **15.0+** 的 Mac，面向 **18** 岁及以上的个人 Google 账号，并提供给 Google AI Plus、Pro 和 Ultra 用户，下载入口为 [gemini.google/mac](https://gemini.google/mac)。官方没有在这篇署文里写 Windows 可用性，我就不补，也不要把它写成已经面向全球或不限订阅。

同日另一篇 [blog.google 署文](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)标题为 “Introducing Tool Retrieval in the Gemini API”，作者为 Gemini API 产品经理 Lucia Loher 与 Google DeepMind 研究科学家 Nora Kassner，`pubDate` UTC **18:00:00 · 11-19** ≈ 北京 **02:00**。官方写 Tool Retrieval 现以预览形式在 Gemini Interactions API 中提供：智能体连接数十甚至上百个工具时，不必每次都发送完整参数 schema。开启方式是在请求中加入 `tool_search`，并对希望暂缓加载的工具设置 `defer_loading: true`；模型仍能看到这些工具的名称和描述，参数 schema 需要时再在同一次请求里加载。最常用的工具可以仍预先加载，该能力与前缀缓存兼容，也可对远程 MCP 服务器设置 `defer_loading: true`。若自行维护工具注册表，还可把 `tool_search` 设为 `"execution": "client"`。计价方面，官方写 Tool Retrieval 没有单独收费，输入和输出仍按所用模型的标准费率计费；打开 `tool_search` 会增加一小块固定的输入 token，此后被加载的 schema 按输入计费。该能力适用于 Gemini **3.6** 及之后的模型，包括所有 Gemini 4 模型。不要把「降低 token / 更准选工具」写成已公布的统一节省比例。

### 2. 出格谁来拦：Semantic governance policies（Preview），以及跨云的 Agent Anomaly Detection（Private Preview）

这两篇都是 **11-20** 的 [Google Developers Blog](https://developers.googleblog.com/) 署文，要分开档位来看。

**Semantic governance policies 以 Preview 形式出现在 Gemini 平台。** 署文标题为 [“Check what your AI agents do before they do it, with Semantic governance policies”](https://developers.googleblog.com/check-what-your-ai-agents-do-before-they-do-it-with-semantic-governance-policies/)，栏面日期 **Nov. 20, 2026**，作者为 Deepti Sehrawat。官方写它在工具调用真正执行前做两道检查：一是你用自然语言写下的规则，二是这次调用有没有偏离用户原来的请求（后一项默认开启，用来防劫持）；两次检查都通过才会执行。目前支持的策略执行点是 Agent Gateway，需要把智能体的出口流量都走 Agent Gateway；模型给出工具调用后，由 Gateway 先送给策略引擎，再用一个 LLM judge 对照对话、系统说明、工具描述和你的规则来判定。若未通过，引擎会替换响应内容（含工具调用）。官方举例：在财报发布前，把未公开的季度结果发给个人 Gmail 或外部投资人会被规则拦住；若智能体读到文档里夹带的隐藏指令、要去删除文件夹，则会被用户意图检查拦住。创建方式可在 Google Cloud 控制台，或使用官方给出的 `gcloud beta ai semantic-governance-policies create`。今晚打开的官方页还写：判定来自 LLM，结果可能不稳定，建议先用 dry run 模式查看记录再改成强制执行；流式模型响应不会被评估；只含文本、不采取行动的回复也不会被评估。它补充而不是取代 IAM、Agent Gateway 访问策略、Model Armor，以及异步运行的 Agent Anomaly Detection，也补充而不是取代信息披露控制以及法律与合规审查。这是 Preview，不要写成已全面开放，或已经可以替代合规审查，也不要把示例规则写成已对所有客户生效的默认策略。

**Agent Anomaly Detection 的 Private Preview 扩到 Google Cloud 之外（不是该功能的首次发布）。** 署文标题为 [“Agent Anomaly Detection: Safeguarding agents across other clouds”](https://developers.googleblog.com/agent-anomaly-detection-safeguarding-agents-across-other-clouds/)，栏面日期 **Nov. 20, 2026**，作者为 Gopi Subburaja Alagar、Arvind Chaudhary。须与 **2026-09-16** 的首次 Private Preview 介绍区分：本条是跨云监控说明。官方写，此前覆盖的是跑在 Google Cloud 上的智能体，例如 Agent Runtime、Cloud Run 和 GKE；现在它从 traces 和日志工作，不必访问智能体运行时。遥测需经 Telemetry API 到达你的 Google Cloud 项目，并遵循 OpenTelemetry 约定。官方写，用 Agent Development Kit（ADK）for Python **2.12.0** 或更高版本，可通过 ADK 的 Google Cloud exporters 产出这类遥测，并用 Workload Identity Federation 换取短期凭证，配置文件不含密钥。署文称通常 **30** 分钟内会出现在 Monitored agents 列表，这只表示已被发现、可以启用；启用后（也可在发现时自动登记）才开始分析。模型和工具调用仍在原处运行，分析在带外进行。官方举例在 AWS Lambda 上的库存智能体和 Microsoft Foundry 上的客服智能体做了测试，并写目前这意味着用 ADK for Python 构建的智能体；Google Cloud 之外的发现结果只出现在 Agent Anomaly Detection 控制台。须申请 Private Preview 访问，不要写成已对所有云上智能体普遍可用，也不要把「**30** 分钟内出现在列表」写成已经开始告警。

### 3. 先看它跑在哪：Inkling 2 Mini，AMD 的 NPU，以及 Windows 上把模型拆到多台电脑的开发者预览

**Thinking Machines Lab 发布 Inkling 2 Mini（官方日期 Nov 20, 2026）。** [官方新闻页](https://thinkingmachines.ai/news/inkling-2-mini/)标题为 “Introducing Inkling 2 Mini”。官方写它是 looped transformer，中间层会对每个 token 运行三次，从而在每个 token 上施加更多推理，并用更少的 token 得到正确答案，尤其是在依赖推理质量的智能体编程任务上；并写它在 DeepSWE v1.1（**48.2%**）和 Vals Index v2.2（**46.5%**）等基准上，领先所有总参数少于 **100B** 的开源权重模型，也比表现相近的模型更快。今晚打开的官方页还写：它是混合专家模型，总参数 **26.4B**、每个 token 激活 **3.4B**，因循环计算对应 **5.4B** 的权重激活；多数权重以 NVFP4 训练和部署，最后四层为 MXFP8；总内存占用约 **20GB**，官方称可以在消费级笔记本和桌面 AI 电脑上运行，并举例研究人员曾在飞行中用一台 MacBook Pro（M5 Pro，**48GB**）离线跑它、做出可玩的飞行模拟器。试用入口为 [Tinker Playground](https://tinker.thinkingmachines.ai/playground) 与 [Hugging Face 模型页](https://huggingface.co/thinkingmachines/Inkling-2-Mini)。这些参数量、量化格式和约 **20GB** 的占用，以今晚的官方新闻页为准；演示用的 **48GB** 机型不要写成最低门槛。Hugging Face 同日[介绍文](https://huggingface.co/blog/inkling2mini)还写了多模态、**1M** token 上下文等口径，那是介绍文的表述，不要和实验室新闻页混成同一句已经公布的规格。@UnslothAI 于北京时间 **04:13 / 08:31 · 11-21** 宣布它已可在 Unsloth 与 llama.cpp 上运行，并提供 GGUF，其中把该模型写成 **26.4B**、Apache 2.0，并称 4-bit 可在 **16GB** RAM 上运行。这些口径须标明来自 Unsloth，不要写成 Thinking Machines 官方署文，也不要把 **16GB** 写成已公布的统一显存门槛。基准领先只按官方所列范围转述，不是对所有任务或所有闭源模型的比较。

## 今日机会总结

今天的脊柱不是「又发布了一个谁都能在云端点开的模型」，而是**新能力落到自己这边了，先看它跑在哪、能碰什么、出格谁来拦**。Gemini 的 computer use 目前写在美国、英语、Apple Silicon 的 Mac 和 Plus / Pro / Ultra 上；ChatGPT Space 是向符合条件的 Plus 账号推开，共享页还要求对方也有权限。Tool Retrieval、Semantic governance policies 仍是 Preview，Agent Anomaly Detection 的跨云监控是须申请的 Private Preview，USB4 RDMA 还只是即将进入 Insider 频道的开发者预览。Inkling 2 Mini、AMD 的 NPU 和 Hy4 旗舰权重，让「跑在哪」变得更具体，但官方占用、演示机型和第三方量化口径不能合成一个统一门槛；Hy4 的许可也不是 Apache 2.0。旁边还有一批研究署文、预印本和内部工程故事，不要把它们折成已经可采购的正式能力。

若只选三条可执行方向：

1. **先对「它跑在哪一台设备、哪一个账号上」：** 对标 Gemini Mac computer use 的地区、硬件和订阅范围，ChatGPT Space 向 Plus **18+** 的滚动推送，以及 Inkling 2 Mini、Unsloth Desktop 对 XDNA 2 NPU 的支持和 USB4 RDMA 的开发者预览。客户是已经在用这些账号、或准备在本机试验的知识工作者和本地部署团队，卖的是按当前页面对过的开通范围，而不是「新能力已经出现在每个人的桌面上」。
2. **先问它能碰哪些应用、哪些工具，以及共享出去谁能打开：** 对标 Mac computer use 须由你授权应用、关键步骤先批准，Tool Retrieval 按需加载 schema，Space 的共享权限和 Free 用户限制，以及美国 Connected Apps、ChatGPT Health 扩展入口各自的地区与档位。客户是要给人与智能体共用本地文件或协作页面的团队，卖的是访问边界，而不是「它已经可以动你电脑上的一切」。
3. **出格的动作谁来拦，仍要按 Preview / Private Preview 分开：** 对标 Semantic governance policies 的事前检查与 dry run，Agent Anomaly Detection 把 traces 送到你自己的 Google Cloud 项目，以及 OpenAI 对对抗性蒸馏的内部评估。客户是已经在跑智能体、需要治理和审计的团队，卖的是拦截和监测卡位，而不是「合规审查已经可以交给模型」。

## 普通人今天就能做的 3 件事

1. **已经在用 ChatGPT Plus、且年满 18 岁的人，或人在美国、用的是搭载 Apple Silicon 的 Mac：** 先按 [Space 入门说明](https://help.openai.com/en/articles/20001549-getting-started-with-space-in-chatgpt)看侧栏有没有 Space、它是否替换了 Library；若桌面应用里还看不到，先更新到最新版，仍没有就把它理解成账号尚未开放，不要以为所有 Plus 账号已经能用，也不要邀请 Free 用户打开共享页。人在美国、使用英语、Mac 为 Apple Silicon 且系统为 macOS Sequoia **15.0+**、年满 **18** 岁的个人 Google 账号，并且是 Google AI Plus、Pro 或 Ultra，可按 [Mac computer use 说明](https://blog.google/innovation-and-ai/products/gemini-app/computer-use-mac/)到 [gemini.google/mac](https://gemini.google/mac) 下载，只授权需要的应用，关键步骤先批准再执行。官方未写 Windows 或中国可用性的，就不必寻找并不存在的入口。
2. **要在本机或几台电脑上跑模型、或已经在给智能体接工具的人：** 想试 Inkling 2 Mini 的，以 [官方新闻页](https://thinkingmachines.ai/news/inkling-2-mini/)的 Tinker 与 Hugging Face 入口为准，官方写总内存占用约 **20GB**，不要把 Unsloth 所称的 **16GB** 4-bit、或演示用的 **48GB** MacBook 写成统一门槛。有符合条件的锐龙 AI 电脑的，可按 [Unsloth 的 AMD NPU 文档](https://unsloth.ai/docs/get-started/install/amd/npu)查看支持范围。想用 USB4 把一个模型拆到多台电脑上的，先读 [微软这篇开发者预览说明](https://techcommunity.microsoft.com/blog/microsoftusbblog/introducing-rdma-over-usb4%c2%ae-on-windows-run-larger-local-ai-models-across-pcs/4574602)：它即将面向 Insider Experimental 频道，默认关闭，不要当成已经推给所有 Windows 11 用户。若智能体已经走 Gemini 平台，可按 [Semantic governance policies](https://developers.googleblog.com/check-what-your-ai-agents-do-before-they-do-it-with-semantic-governance-policies/) 先开 dry run，记住流式响应不会被评估；跨云监测要以 [Agent Anomaly Detection](https://developers.googleblog.com/agent-anomaly-detection-safeguarding-agents-across-other-clouds/) 的 Private Preview 申请和 traces 送出范围为准。
3. **在 Gemini、OpenAI 或 Amazon Bedrock 上给智能体接工具或语音的开发者：** Tool Retrieval 按 [Gemini API 说明](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)在 Interactions API 的预览里按需加载 schema，不要默认每次都把全部工具参数塞进请求。语音会话要以官方文档里的模型 ID [`gpt-live-1.1`](https://developers.openai.com/api/docs/models/gpt-live-1.1) 为准，standby 每分钟 **$0.02** 只适用于官方写明的 WebRTC 暂停推理。从较新前沿模型起，按 [Keep the prefix unchanged](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged) 尽量只追加、不改更早的消息，以免后面的推理被丢掉。Bedrock 的 Web Search 按今晚打开的 [What’s New](https://aws.amazon.com/about-aws/whats-new/2026/11/web-search-amazon-bedrock/) 核对语种和区域，不要假定官方未列出的法兰克福或中国区域已经提供。本轮没有核验过新的跟练视频，也就不列教程。
